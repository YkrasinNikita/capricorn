# «Капри» — план изменений и промты для нейросети

Документ для выполнения задач в отдельных сессиях. Каждая задача самодостаточна:
в новую сессию вставляется **мастер-промт** (раздел 1), затем **карточка задачи** (раздел 4).

---

## 1. Мастер-промт (вставлять первым)

```text
Ты работаешь с проектом «Капри» — офлайн-ориентированный голосовой ассистент для Windows.

КОНТЕКСТ ПРОЕКТА
- Папка: C:\Users\user\Desktop\capricorn-main
- Стек: Python 3.14, PySide6 (GUI), Vosk (офлайн STT), edge-tts / Silero / SAPI (TTS),
  Ollama (локальная LLM), опционально Anthropic Claude, Win32-автоматизация (pywin32/ctypes).
- Точка входа: main.py (DEFAULTS, класс Capri, цепочка ответов).
- Маршрутизация команд: actions.py (~1950 строк, метод handle/handle_one, десятки regex-веток).
- Голос: voice.py (Listener, Speaker, google_stt, обработка аудио).
- Локальный ИИ: local_ai.py. Облачный ИИ: ai.py. Автоматизация: automation.py, media.py.
- Персона и фразы: persona.py. Аватар: avatar.py. Настройки: config.json (в git не входит).

ПРАВИЛА РАБОТЫ
1. Не переписывай проект целиком. Делай минимальные изменения в рамках одной задачи.
2. Сохраняй обратную совместимость: существующие команды, настройки и импорты должны работать.
3. Ничего не удаляй без явной необходимости; незнакомый код считай рабочим.
4. Стиль — как в проекте: простые функции, русские комментарии допустимы, без новых тяжёлых зависимостей.
5. Всё, что можно сделать локально, делай локально. Новые сетевые вызовы — только по явному согласию.
6. Не коммить config.json, логи, модели и кэш. Проверь .gitignore.
7. В конце каждой задачи: запусти `python -m compileall -q .` и убедись, что приложение стартует
   (`python main.py` или run.bat). Если запуск GUI невозможен — опиши, что проверял.

ФОРМАТ ОТВЕТА
- Кратко: что изменено и почему.
- Список файлов (создан/изменён) с назначением.
- Как проверить руками (2–5 шагов).
- Риски и что осталось за рамками задачи.
```

## 2. Как работать с планом

1. Бери задачи строго по порядку приоритетов: **P0 → P1 → P2 → P3**.
2. Одна сессия = одна задача. Не смешивай рефакторинг и фичи.
3. Перед задачей попроси нейросеть: «сначала прочитай указанные файлы и покажи план, потом меняй код».
4. После задачи сохраняй рабочую версию (архив/коммит), чтобы можно было откатиться.
5. P0 делать до всех фич: иначе конфликты в actions.py будут повторяться.

## 3. Задачи

### P0 — фундамент (без этого фичи дорожают)

#### T1. Разбить actions.py на пакет
**Файлы:** `actions.py` → `actions/__init__.py`, `actions/core.py`, `actions/system.py`, `actions/apps.py`, `actions/web.py`, `actions/files.py`, `actions/keys.py`, `actions/fallback.py`.

**Шаги**
- Перед началом сохрани копию `actions.py` (например, `actions.py.bak` вне проекта или в архиве).
- Вынести группы обработчиков по смыслу: система (громкость/яркость/питание), программы, браузер/YouTube, файлы/папки, клавиши, анализ ПК, fallback.
- Оставить публичный API: `from actions import Actions, Reply` и методы `handle`, `handle_one`, `fallback`; утилиты `norm`, `translit`, `parse_number` — доступны из пакета.
- Реестр интентов: список `(regex, handler, name)` вместо длинной цепочки `if/elif`, с сохранением порядка срабатывания.
- Никаких изменений в текстах ответов и логике команд.

**Готово, когда**
- `from actions import Actions, Reply` работает без правок в main.py.
- Старый `actions.py` удалён (не оставлять одновременно файл и пакет с тем же именем).
- Число строк в любом новом модуле < 400.
- Все прежние команды отвечают так же (проверить 10–15 вручную списком).
- `python -m compileall -q .` без ошибок.

**Файлы:** `main.py`, новый `logging_setup.py`.

**Готово, когда**

### P1 — основные функции

#### T5. Планировщик и напоминания
**Файлы:** новый `scheduler.py`, `reminders.json`, интеграция в `actions/` и `main.py`.

**Команды:** «напомни через 10 минут …», «напомни в 18:30 …», «какие напоминания», «отмени напоминание …».

**Шаги**
- Хранилище `reminders.json`: id, текст, время (ISO), повтор (нет/ежедневно).
- Поток-планировщик с точностью до секунды, без busy-loop.
- Озвучивание через callback в `Capri` (не импортировать GUI внутрь scheduler).
- Переживание перезапуска: просроченные — озвучить один раз при старте.
- Разбор русского времени: «через N минут/часов», «в HH:MM», «завтра в HH:MM».

**Готово, когда**
- Напоминание срабатывает после перезапуска приложения.
- Отмена и список работают.
- Поток корректно завершается при выходе.

---

#### T6. Заметки и память
**Файлы:** новый `notes.py`, `notes.json`, интеграция в `actions/`.

**Команды:** «запомни, что …», «что ты знаешь о …», «покажи заметки», «удали заметку …».

**Шаги**
- Заметка: id, текст, теги, дата создания/изменения.
- Поиск по подстроке без регистра + простой ранжирующий скор (совпадения слов).
- Голосовой ответ — 1–2 самые релевантные заметки, остальное «ещё N».
- Лимит хранения и дедупликация похожих записей.

**Готово, когда**
- Заметки сохраняются между запусками.
- Поиск находит по словоформе-подстроке («встреча» → «встречу»).
- Нет падений на пустом/битом файле.

---

#### T7. Кэш TTS
**Файлы:** `voice.py`, `cache/tts/`.

**Шаги**
- Ключ: sha256 от (текст + голос + движок + скорость/тон).
- Попадание — играть файл без синтеза; промах — синтез и сохранение.
- LRU-лимит по размеру (например, 200 МБ), фоновая очистка.
- Не кэшировать слишком длинные тексты (> 500 символов).

**Готово, когда**
- Повторная фраза звучит мгновенно и без обращения к сети.
- Кэш не растёт бесконечно.
- При повреждённом файле — пересинтез, а не ошибка.

---

#### T8. Единая цепочка ИИ с фолбэками
**Файлы:** `local_ai.py`, `ai.py`, новый `ai_router.py`, `main.py`.

**Шаги**
- Один интерфейс `ask_ai(text, context) -> (answer, source)`.
- Порядок: локальная модель → Claude (если ключ) → офлайн-заготовка.
- Таймауты (например, 20 с локально, 15 с облако), 1 повтор, понятные ошибки в лог.
- Не отправлять в облако, если включён privacy-режим (см. T9).
- В ответе сохранять источник — для отладки и озвучки.

**Готово, когда**
- При выключенном Ollama ассистент отвечает через Claude или заготовку, не зависает.
- При ошибке API приложение не падает.
- Время ответа ограничено таймаутом.

---

#### T9. Режим приватности
**Файлы:** `main.py`, `voice.py`, `ai_router.py`, UI настроек.

**Шаги**
- Флаг `privacy_mode` в конфиге; при включении: только Vosk, только локальная LLM, облачный TTS запрещён.
- Индикатор в UI/трее (щит/цвет).
- Переключение без перезапуска, где возможно; иначе — честное сообщение.
- В лог писать, какой режим активен, без текста команд.

**Готово, когда**
- При включённом режиме нет исходящих запросов (проверить лог/сниффером).
- Google STT не вызывается даже при `use_google_stt: true`.
- Пользователь видит, что режим включён.

### P2 — расширяемость и качество

#### T10. Плагины-навыки
**Файлы:** `actions/plugins/`, реестр в `actions/`.

**Шаги**
- Плагин = модуль с `NAME`, `PATTERNS`, `handle(cmd, match) -> Reply | None`.
- Автоподключение из папки, включение/отключение через конфиг.
- Ошибка плагина изолируется и логируется.
- Перевести 2–3 существующих мелких навыка как пример.

**Готово, когда**
- Новый навык добавляется одним файлом без правки ядра.
- Отключённый плагин не влияет на маршрутизацию.

---

#### T11. Улучшение STT
**Файлы:** `voice.py`, опционально `stt_whisper.py`.

**Шаги**
- Настроить Vosk: грамматика/подсказки под команды, порог тишины, отсечение шума.
- Убрать ложные срабатывания на тишине/фоновом шуме.
- Добавить альтернативный бэкенд (faster-whisper/whisper.cpp) за тем же интерфейсом `Listener`.
- Небольшой набор фраз (20–30) для замера: сколько распознано верно.

**Готово, когда**
- Выбор бэкенда в конфиге.
- Замер до/после по одному и тому же набору.
- Основной путь (Vosk) остаётся офлайн и по умолчанию.

---

#### T12. Единое окно настроек
**Файлы:** новый `settings_dialog.py`, `main.py`, удаление/замена старых диалогов.

**Шаги**
- Вкладки: Голос (микрофон, TTS, скорость), ИИ (модель, ключ, privacy), Поведение (поиск, болтовня), Напоминания/Заметки, О программе.
- Валидация полей, «Применить» без перезапуска где возможно.
- Кнопка «Проверить микрофон» и «Проверить TTS».

**Готово, когда**
- Все прежние настройки доступны из одного окна.
- Невалидные значения не сохраняются.
- Конфиг после сохранения проходит миграцию (T2).

---

#### T13. Сборка и упаковка
**Файлы:** `build.spec` (PyInstaller), `build.bat`, `version.py`, README.

**Шаги**
- Собрать onedir-версию с ассетами, без моделей (модели — отдельным шагом).
- Первый запуск: проверка моделей, предложение скачать.
- Версия в `version.py`, вывод в «О программе» и лог.
- Чистый запуск на машине без Python (проверить в отдельной папке).

**Готово, когда**
- `build.bat` даёт запускаемую папку.
- Приложение стартует без установленного Python.
- Отсутствие модели объясняется понятным сообщением.

### P3 — эксперименты (после стабилизации)

#### T14. RAG по заметкам и документам
Локальные эмбеддинги через Ollama, индекс в `index/`, ответы со ссылкой на источник. Критерий: ответ на вопрос по 2–3 своим документам без облака.

#### T15. Эмоции и lip-sync аватара
События `emotion` из ответа (радость/нейтрально/ошибка), синхронизация рта с длительностью аудио. Критерий: смена эмоции не ломает анимацию и не грузит CPU.

#### T16. CI и релизы
GitHub Actions: `pytest` на push, сборка артефакта по тегу. Критерий: зелёный прогон на чистом раннере.
